A Go library for interacting with Myra Security API.

## Example usage

```go
package main

import (
	"context"
	"log"
	"os"

	myrasec "github.com/Myra-Security-GmbH/myrasec-go/v2"
)

func main() {
	api, err := myrasec.New(os.Getenv("MYRA_API_KEY"), os.Getenv("MYRA_API_SECRET"))
	// Alternatively you can use the API token for authentication, too
	// api, err := myrasec.NewWithToken(os.Getenv("MYRA_API_TOKEN"))
	if err != nil {
		log.Fatal(err)
	}

	ctx := context.Background()

	domains, err := api.ListDomainsContext(ctx, map[string]string{"pageSize": "100"})
	if err != nil {
		log.Fatal(err)
	}

	for _, d := range domains {
		log.Println(d.Name)
	}
}
```

## Release

Every SDK operation must call a route that the public API documentation lists.

- `testdata/documented-routes.txt` is generated by `./scripts/update-documented-routes.sh` from the production API documentation (`https://apiv2.myracloud.com/api/doc.json`): one `METHOD /path` line per documented operation, every path parameter replaced by `*`. Never edit it by hand. The script only fetches over https, fails on an unexpected path or `basePath`, and keeps the existing file when the download fails or lists no operations. It needs `curl` and `jq`.
- `testdata/pending-routes.txt` is maintained by hand. It lists routes the SDK already calls that production does not document yet, each with a reason. Keep it empty whenever possible.
- `TestEveryOperationIsDocumented` checks every operation in `initializeMethods()` against both files. `TestPendingRoutesAreNotDocumentedYet` fails once a pending route appears in the generated file, and `TestPendingRoutesAreCalledBySDK` fails when no operation calls a pending route any more, so the exceptions get removed.

What CI guarantees:

- On every push and pull request, the tests run against the committed files. A change can add a route to `pending-routes.txt`, so this alone does not prove that a route is documented in production.
- On every `v*` tag, the release workflow refreshes `documented-routes.txt` from production and fails the release when it differs from the committed file or when the tests fail against it. A release therefore only ships when the committed snapshot matches production and every operation is documented there or listed, with a reason, in `pending-routes.txt`.

Before tagging a `v*` release:

1. Run `./scripts/update-documented-routes.sh`.
2. Remove every route from `pending-routes.txt` that the tests now report as documented.
3. Run `go test ./...` and commit both files.

When the test reports an operation as undocumented, either the route must be documented in the API first, or the operation must be removed from the SDK.
